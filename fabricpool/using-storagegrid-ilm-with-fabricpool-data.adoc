= 配置 StorageGRID ILM 以進行 FabricPool 數據
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
您可以將此簡單的範例原則作為制定您自己的 ILM 規則和原則的起點。

本範例假設您正在為位於科羅拉多州丹佛市單一資料中心、包含四個儲存節點的 StorageGRID 系統設計 ILM 規則和 ILM 原則。本範例中的 FabricPool 資料使用名為 `fabricpool-bucket`的儲存桶。


CAUTION: 以下 ILM 規則和原則僅為範例。設定 ILM 規則的方法有很多種。在啟動新原則之前，請模擬，以確認其能夠按預期保護內容免受資料遺失。若要深入瞭解，請參閱 link:../ilm/index.html["使用 ILM 管理物件"]。


CAUTION: 為避免資料遺失，請勿使用會使 FabricPool 雲端分層資料過期或遭刪除的 ILM 規則。將保留期間設為 *forever*，以確保 FabricPool 物件不會被 StorageGRID ILM 刪除。

.開始之前
* 您已審閱 link:best-practices-ilm.html["搭配 FabricPool 資料使用 ILM 的最佳實務做法"]。
* 您已使用 link:../admin/web-browser-requirements.html["支援的網頁瀏覽器"] 登入 Grid Manager。
* 您有link:../admin/admin-group-permissions.html["ILM 或 root 存取權限"]。
* 如果您是從低於 11.7 的 StorageGRID 版本升級到 StorageGRID 12.0，則您已設定了要使用的儲存資源池。通常，您應該為每個用於儲存資料的 StorageGRID 站台建立一個儲存資源池。（從 11.7 版開始，系統會自動為每個站台建立儲存資源池。）
+

NOTE: 如果您最初安裝的是 StorageGRID 11.7 或 11.8，則此先決條件不適用。當您最初安裝這兩個版本中的任何一個時，系統會自動為每個站台建立儲存資源池。



.步驟
. 建立一個僅適用於 `fabricpool-bucket`中資料的 ILM 規則。此範例規則建立銷毀編碼複本。

. 建立 ILM 原則並選擇這兩條規則。由於複寫規則未使用任何篩選器，因此它可以作為該原則的預設（最後）規則。
. 將測試物件匯入網格。
. 使用測試物件模擬原則，以驗證其行為。
. 啟動原則。


啟用此原則後，StorageGRID 將如下放置物件資料：

* 從 FabricPool 分層的資料 `fabricpool-bucket`將使用 2+1 糾刪碼方案進行糾刪碼編碼。兩個資料片段和一個同位元檢查片段將放置在三個不同的儲存節點上。
* 所有其他儲存桶中的所有物件都將進行複寫。將建立兩個副本，並分別放置在兩個不同的儲存節點上。
* 這些副本將永久保留在 StorageGRID 中。StorageGRID ILM 不會刪除這些物件。
