= StorageGRID 中使用儲存池的站台遺失保護
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
如果您的 StorageGRID 部署包含多個站台，則可以使用複寫和銷毀編碼以及適當設定的儲存資源池來啟用站台遺失保護。

複寫和銷毀編碼需要不同的儲存資源池組態：

* 若要使用複寫來保護站台遺失，請使用在 StorageGRID 安裝過程中自動建立的站台專屬儲存資源池。然後建立含有 link:create-ilm-rule-define-placements.html["放置指示"] 的 ILM 規則，指定多個儲存資源池，以便將每個物件的複本放置在每個站台上。
* 若要使用銷毀編碼進行站台遺失保護，link:guidelines-for-creating-storage-pools.html#guidelines-for-storage-pools-used-for-erasure-coded-copies["建立包含多個站台的儲存資源池"]。然後建立 ILM 規則，使用由多個站台組成的儲存資源池以及任何可用的銷毀編碼方案。



CAUTION: 在設定 StorageGRID 部署以實現站台遺失保護時，您還必須考量 link:data-protection-options-for-ingest.html["擷取選項"] 和 link:../s3/consistency.html["一致性"] 的影響。



[[replication-example]]
== 複寫範例

預設情況下，在安裝 StorageGRID 期間，會為每個站台建立一個儲存資源池。擁有僅由一個站台組成的儲存資源池，可讓您設定使用複寫進行站台遺失保護的 ILM 規則。在此範例中：

* 儲存資源池 1 包含站點 1
* 儲存資源池 2 包含站台 2
* ILM 規則包含兩個位置：
+
** 透過在網站 1 複製 1 個複本來儲存物件
** 透過在網站 2 複製 1 個複本來儲存物件




ILM 規則設定：

image:ilm_replication_at_2_sites.png["在 2 個站台各複寫 1 個複本"]

image:ilm_replication_make_2_copies_2_pools_2_sites.png["在 2 個站台上各建立 1 份複本 - 站台特定儲存資源池"]

如果一個站台遺失，則可以在另一個站台找到物件的複本。



[[erasure-coding-example]]
== 銷毀編碼範例

擁有由每個儲存資源池多個站台組成的儲存資源池，可讓您設定使用銷毀編碼進行站台遺失保護的 ILM 規則。在此範例中：

* 儲存資源池 1 包含站點 1 至 3。
* ILM 規則包含一個放置位置：使用 4+2 EC 方案透過銷毀編碼將物件儲存在儲存資源池 1 中，該儲存資源池包含三個站台。


ILM 規則設定：

image:ilm_erasure_coding_site_loss_protection_4+2.png["EC 1 儲存資源池 9 個儲存節點 3 個站台"]

在此範例中：

* ILM 規則採用 4+2 銷毀編碼方案。
* 每個物件會切割成四個相等的資料片段，並從物件資料計算出兩個同位元檢查片段。
* 這六個片段分別儲存在三個資料中心站台的不同節點上，以在節點故障或站台遺失時提供資料保護。



NOTE: 銷毀編碼允許用於包含任意數量站台的儲存資源池中，但兩個站台除外。

使用 4+2 銷毀編碼方案的 ILM 規則：

image:ec_three_sites_4_plus_2_site_loss_example_template.png["使用 4+2 EC 方案，透過銷毀編碼在 3 個站台上儲存物件。"]

即使一個站台遺失，資料仍可復原：

image:ec_three_sites_4_plus_2_site_loss_example.png["銷毀編碼 4+2 EC 方案 1 個站台遺失"]
