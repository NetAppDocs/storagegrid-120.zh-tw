= StorageGRID 12.0 的新功能
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
StorageGRID 12.0 擴展了物件儲存容量，提高了對 AI/ML 工作負載的支援，加強了網格聯合，簡化了系統管理，並增強了整個平台的安全性。

有關 StorageGRID 12.0 最新版本中已修復問題和已知問題的詳細資訊，請參閱 https://library.netapp.com/ecm/ecm_download_file/ECMLP3351267["StorageGRID 12.0 版本說明"^]。您必須登入現有 NetApp 帳戶或建立帳戶才能存取發行說明。



[[appliances]]
== 應用裝置

* 儲存容量和成本效率均顯著提高。
* 自動磁碟機韌體升級可提高系統可靠性並降低維護例行成本。




[[artificial-intelligence-ai-and-machine-learning-ml]]
== 人工智慧（AI）和機器學習（ML）

* link:../tenant/what-is-branch-bucket.html["分支桶"] 允許建立儲存桶的時間點版本，以便更快速地從勒索軟體中恢復，並提供隔離的資料集以進行測試和實驗。
* S3 快取階層可提高 AI/ML 訓練的效能。




[[capacity]]
== 容量

StorageGRID 現在支援一兆個物件，是先前限制的兩倍以上。請參閱 https://fusion.netapp.com/["NetApp Fusion 工具"^]以調整 StorageGRID 的規模和設計。



[[cassandra-updates]]
== Cassandra 更新

StorageGRID 現在使用較新版本的 Cassandra 進行中繼資料儲存。此版本的 Cassandra 能更有效率地使用磁碟空間，以儲存更多中繼資料。

您link:../upgrade/index.html["從 StorageGRID 11.9 升級至 12.0"]之後，中繼資料格式更新將在背景執行一到三天。在此期間，某些涉及中繼資料串流的維護程序（例如擴充）將會停用。

請參閱 link:../upgrade/performing-upgrade.html#upgrade-other-nodes["升級其他節點"]。



[[federation]]
== 聯邦

* 您現在可以link:../admin/managing-users.html#import-federated-users["最多可匯入 100 位聯合用戶"]至 StorageGRID。
* 現在您可以link:../ilm/configuring-regions-optional-and-s3-only.html["修改預設區域"]用於 S3 儲存桶。此功能在管理資料區域和法規遵循方面提供了更大的靈活度。
* 現在，您可以設定啟用了 S3 物件鎖定的儲存桶之間的跨網格複寫。請參閱 link:../admin/grid-federation-what-is-cross-grid-replication.html#cgr-with-ol["使用 S3 物件鎖定進行跨網格複寫"]。
+
NetApp 建議僅在 StorageGRID 12.0 來源儲存桶和目的地儲存桶之間使用此功能。但是，此功能也支援在已停用 S3 物件鎖定的 StorageGRID 11.9 來源儲存桶和已啟用 S3 物件鎖定的 StorageGRID 12.0 目的地儲存桶之間使用。





[[manageability]]
== 可管理性

* 改善後link:../maintain/decommission-procedure.html["退役程序"]可減少時間和複雜性，進而提高作業效率。
* 改進的強全域一致性行為，可在網格具有三個或更多站台時，為用戶端請求提供站台故障容錯能力。
+
** StorageGRID 12.0 及更高版本的新安裝將預設使用仲裁語義（當 link:../s3/consistency.html["強全球一致性"] 已設定時）。
** 如果從 StorageGRID 11.9 升級至 StorageGRID 12.0，升級後的網格將保留先前的強全域一致性行為。





NOTE: 如果需要回復至先前的強全域一致性行為，請參閱 https://kb.netapp.com/hybrid/StorageGRID/Object_Mgmt/Configuring_StorageGRID_quorum_semantics_for_strong-global_consistency["設定 StorageGRID 仲裁語義以實現強全域一致性"^]以取得相關說明。

* 啟動記錄上傳至 link:../admin/configure-autosupport-grid-manager.html["AutoSupport"] 的功能有助於提升支援回應能力。
* 縮短 https://docs.netapp.com/us-en/storagegrid-appliances/index.html["應用裝置"^]重新開機時間可最大化地減少停機，進而提高整體系統可用度。
* link:../maintain/move-adc-service.html["移動 ADC 服務的能力"] 將 ADC 服務遷移到另一個儲存節點可以提高管理主機 ADC 服務的儲存節點的靈活度和彈性。您可以在退役儲存節點或將儲存節點轉換為僅資料節點之前遷移 ADC 服務。
* 為了最大化資料儲存設備容量，您可以link:../maintain/convert-to-data-only-node.html["將儲存節點轉換為僅資料節點"]，這會使該節點上的中繼資料遷移至組合或僅中繼資料的儲存節點。
* 任何管理節點都能夠 link:../maintain/selecting-node-recovery-procedure.html["恢復任何其他節點"]（主管理節點除外），進而增強系統恢復和容錯能力，提高整體可靠性。
* 用戶現在可以使用 S3 儲存桶來link:../monitor/configure-log-management.html#use-a-bucket["長期儲存稽核日誌"]。




[[security]]
== 安全性

* 更強大的資料加密和完整性保護可提供更高的安全性和效能。
* 提高儲存密碼的安全性可以降低未經授權存取的風險。
* link:../admin/manage-external-ssh-access.html["SSH 預設為封鎖狀態。"]以增強安全性，同時允許受控存取。




[[tenant-groups]]
== 租戶群組

* 您現在可以link:../tenant/manage-groups.html["設定新的 S3 信任原則"]支援 AssumeRole API。AssumeRole 功能提供短期憑證，以增強安全性並實現靈活的存取控制。
* 每個儲存桶物件數量配額可更好地控制和管理儲存資源。




[[user-interface]]
== 使用者介面

* 網格管理器和租戶管理器的使用者選單中提供深色主題和系統主題設定。
* 稽核和 syslog 伺服器頁面已重新命名為 link:../monitor/configure-log-management.html["日誌管理"]，並經過重構，新增了將日誌儲存在系統儲存桶中以進行備份的功能。
* 舊版網格拓樸頁面已移除。在過去的幾個 StorageGRID 版本中，該頁面上的操作和計量已移轉至 Grid Manager 中的其他頁面，特別是移轉至link:../monitor/viewing-nodes-page.html["節點頁面"]。
